## Defect Description

`_build_thread` in [src/micronote/utils/thread.py](../../src/micronote/utils/thread.py#L10) builds a reply tree by indexing docs by `activity.object.id` and linking children via `activity.object.inReplyTo`. The tree is then flattened by a recursive `_flatten` closure at [line 64](../../src/micronote/utils/thread.py#L64):

```python
def _flatten(node, level=0):
    node["_level"] = level
    thread.append(node)
    for snode in sorted(
        idx[node["activity"]["object"]["id"]]["_nodes"],
        key=published_of,
    ):
        _flatten(snode, level=level + 1)
```

There is no visited-set or depth limit. A self-referencing document (where `inReplyTo == id`) produces a cycle in `_nodes`: the doc is appended to its own `_nodes` list at [line 57](../../src/micronote/utils/thread.py#L57). `_flatten` then recurses into itself without bound until `RecursionError` (default limit ~1000) is raised, crashing the entire request with HTTP 500.

## Impact

- `/note/<id>` and `/admin/thread?oid=<id>` return HTTP 500 whenever any doc in the fetched reply set has `inReplyTo` equal to its own `id`.
- The crash occurs server-side; the request thread is consumed by ~1000 stack frames before the exception propagates.
- Maliciously crafted remote notes (federation input) can trigger this by publishing a Note with `inReplyTo` set to its own URL — no attacker control beyond a valid federation message is required.

## Root Cause Analysis

The `seen` set used in `MicroblogPubBackend._handle_replies` ([activitypub.py:629](../../src/micronote/activitypub.py#L629)) guards the ingest-side thread walk, but `_build_thread` operates on stored docs with no equivalent guard. A self-referencing `inReplyTo` that slipped past ingest (or was manually crafted) is not filtered at [line 34](../../src/micronote/utils/thread.py#L34) (the type check only filters non-dict objects, not cycles).

## Remediation Plan

Add a `visited` set to `_flatten` and skip already-visited node IDs:

```python
visited: set[str] = set()


def _flatten(node, level=0):
    node_id = node["activity"]["object"]["id"]
    if node_id in visited:
        return
    visited.add(node_id)
    node["_level"] = level
    thread.append(node)
    for snode in sorted(idx[node_id]["_nodes"], key=published_of):
        _flatten(snode, level + 1)
```

Additionally, filter self-referencing docs out of `replies2` before tree building:

```python
replies2 = [rep for rep in replies2 if rep["activity"]["object"]["id"] != rep["activity"]["object"].get("inReplyTo")]
```

## Verification

Reproduce by inserting a doc into the DB where `activity.object.id == activity.object.inReplyTo` and requesting `/note/<id>`; expect an unbounded recursion crash. After the fix, expect a normal 200 response with the self-referencing doc excluded from the thread.
