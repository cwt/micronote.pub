# Unhandled ActivityUnavailableError in worker cache_object and cache_actor Crashes on Remote 401 Unauthorized

## Defect Description

In `cache_object` ([src/micronote/worker.py#L165-L187](../../src/micronote/worker.py#L165-L187)):

```python
def cache_object(job) -> None:
    iri = job["iri"]
    try:
        activity = ap.fetch_remote_activity_sync(iri)
        log.info(f"activity={activity!r}")

        obj = activity.get_object_sync()
        DB.activities.update_one(
            {"remote_id": activity.id},
            {
                "$set": {
                    "meta.object": obj.to_dict(embed=True),
                    "meta.object_actor": activitypub._actor_to_meta(obj.get_actor_sync()),
                }
            },
        )
```

When an `Announce` (boost) or `Like` activity references a remote note on a server with Mastodon's `AUTHORIZED_FETCH=true` (Secure Mode), or with private profile visibility:
`obj.get_actor_sync()` performs an unauthenticated HTTP GET request. The remote server responds with `HTTP 401 Unauthorized`, raising `active_boxes.errors.ActivityUnavailableError`:

```text
ERROR:micronote.tasks:failed to cache object for https://mas.to/users/veer66/statuses/117279205452392879/activity
Traceback (most recent call last):
  File "/app/.venv/lib64/python3.14/site-packages/micronote/worker.py", line 177, in cache_object
    "meta.object_actor": activitypub._actor_to_meta(obj.get_actor_sync()),
  File "/app/.venv/lib64/python3.14/site-packages/active_boxes/activitypub.py", line 740, in get_actor_sync
    return _run_sync(self.get_actor())
  ...
active_boxes.errors.ActivityUnavailableError: ActivityUnavailableError("unable to fetch https://mastodon.social/users/titipat, unknown error: 401, message='Unauthorized', url='https://mastodon.social/users/titipat'", payload=None, status_code=503)
```

Because `cache_object` calls `obj.get_actor_sync()` without exception handling, the error propagates to the top-level handler, which logs a failure and raises. The worker retries the job 9 times before permanently abandoning it.

---

## Impact

- Boosted/announced activities from remote Fediverse instances fail to cache their objects and actors.
- Worker tasks fail and back off repeatedly, degrading ingestion throughput.
- Legitimate boosted posts cannot be rendered with author attribution.

---

## Root Cause Analysis

1. An HTTP `401 Unauthorized` in ActivityPub does not mean the remote server blocked the instance; it indicates that the remote server requires an HTTP Signature on GET requests (Authorized Fetch / Secure Mode) or that the profile has restricted visibility.
2. `cache_object` and `cache_actor` assumed remote actor dereferencing always succeeds or raises only `ActivityGoneError` / `ActivityNotFoundError`.
3. Lack of fallback handling to the object's `attributedTo` IRI when actor dereferencing is restricted.

---

## Remediation Plan

1. Wrap `obj.get_actor_sync()` in `cache_object` with exception handling, falling back to `obj.attributedTo` if the remote profile cannot be dereferenced.
2. Wrap `activity.get_actor_sync()` in `cache_actor` with fallback to `activity.actor`.
3. In `process_new_activity` and `cache_object`, guard against unhandled `ActivityUnavailableError` on remote object and reply fetches so the worker does not fail and retry indefinitely on permanent 401 Unauthorized responses.

---

## Resolution

- In [src/micronote/worker.py](../../src/micronote/worker.py), updated `cache_object` to wrap `obj.get_actor_sync()` and `activity.get_object_sync()` with error guards catching `(Error, Exception)` and `ActivityUnavailableError`.
- If the object actor profile cannot be fetched (e.g. 401 Unauthorized under Mastodon Authorized Fetch or private profiles), it falls back cleanly to the note's `attributedTo` identifier without throwing an unhandled exception or aborting the job.
- Updated `cache_actor` to safely catch actor dereferencing failures and fall back to `activity.actor`.
- In `process_new_activity`, guarded `activity.get_object_sync()` and `ap.fetch_remote_activity_sync(note.inReplyTo)` against uncaught `ActivityUnavailableError`.
- Added unit tests in [tests/test_cache_object.py](../../tests/test_cache_object.py) verifying fallback handling on 401 Unauthorized actor responses and error suppression.
