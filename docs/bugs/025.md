# YouTube Link Cards Missing — Consent-Gated Watch-Page Scrape Silently Drops og_metadata

## Defect Description

Notes that contain a YouTube link render no link card / thumbnail, while notes containing GitHub, Microsoft Learn, Instagram, X, and other ordinary links render cards correctly. The Open Graph pipeline is a background job (`fetch_og_metadata`) that, for each link in a note:

1. HTTP-GETs the link (`opengraph.fetch_og_metadata`).
2. Requires the response `content-type` to start with `text/html`.
3. Parses the body with the `opengraph` package and **only keeps the result if it produced an `og:url`** — `if data.get("url"): res.append(data)`.

The dropped results are then stored via `DB.activities.update_one({"remote_id": iri}, {"$set": {"meta.og_metadata": og_metadata}})` in [handlers.py:176-209](../../src/micronote/handlers.py#L176-L209). The template only renders a card for entries that carry a `url`, so an empty `meta.og_metadata` yields no card.

## Root Cause (machine-confirmed on the production box)

Reproducing the exact fetch from the production egress IP (`cwt-02`) shows why YouTube is the odd one out:

| Fetch (production) | Result |
| --- | --- |
| `GET https://youtu.be/<id>` (redirect-following, app UA) | `200 text/html`, but a **consent-gated JS shell** (`lang="ja-JP"`, `CONSENT` markers, **no `og:url` / `og:image`** meta) |
| `GET https://i.ytimg.com/vi/<id>/hqdefault.jpg` | `200 image/jpeg` ✅ |
| `GET https://www.youtube.com/oembed?…` | clean JSON (`title`, `author_name`) ✅ |

Because the consent shell yields no `og:url`, step 3's `if data.get("url")` is falsy and the link is **silently dropped** (no error, no warning — a plain `continue`). This is why the worker log shows `OG metadata fetched …` with no error while the DB row still holds `meta.og_metadata = []`.

Ground truth pulled from the production DB (`/data/unote/data/cwt_unote_bashell_com.db`, `activities` table):

- The affected outbox note: `outbox | https://unote.bashell.com/outbox/ff8e656dc01308d9 | []`.
- Systematic: every activity whose content references a `youtu` link has `meta.og_metadata` empty or with no YouTube entry — including an inbox KDE note whose `og_metadata` successfully captured `kde.org` and `floss.social` but dropped its own YouTube link.

Ordinary sites are unaffected: they serve plain HTML with standard Open Graph tags and are not IP-gated, so they scrape cleanly from the same egress.

## Impact

- YouTube links in notes show no link card or thumbnail (functional, user-facing degradation of the link-preview feature for a very common link type).
- No crash, no data corruption, no security impact — purely a missing preview.
- The silent-drop makes it invisible in logs, so it was hard to diagnose without inspecting the DB.

## Resolution

Added a YouTube short-circuit in [src/micronote/utils/opengraph.py](../../src/micronote/utils/opengraph.py) that runs **before** the HTML scrape, so YouTube links no longer depend on the consent-gated watch page:

- `_youtube_video_id(url)` — extracts the video ID from `youtu.be/<id>`, `watch?v=`, and `/shorts/`, `/embed/`, `/live/` paths (validated against the 11-char ID shape).
- `_youtube_card(video_id, user_agent)` — builds the card from the **stable thumbnail CDN** (`https://i.ytimg.com/vi/<id>/hqdefault.jpg`) plus the lightweight **oEmbed** endpoint for `title` / `author_name`, with a safe fallback title if oEmbed is unreachable.

The generic scrape path is unchanged for all non-YouTube links.

Tests added in [tests/test_opengraph.py](../../tests/test_opengraph.py): video-ID extraction across URL forms, the stable-endpoint card (asserting only the oEmbed endpoint is hit, never the watch page), and the oEmbed-down fallback. Full suite: 130 passed; `ruff` + `mypy` clean.

## Deployment note (operational follow-up, not part of the code fix)

The fix only affects **future** `fetch_og_metadata` runs. Notes already stored with `meta.og_metadata = []` (e.g. `ff8e656dc01308d9`) will not self-heal. After deploying this change to `cwt-02`, re-enqueue the `fetch_og_metadata` job for existing YouTube-link notes (or directly re-run the job for their IRIs) to backfill their thumbnails.
