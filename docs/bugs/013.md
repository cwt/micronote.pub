## Defect Description

When processing incoming `Announce` (boost) activities in `finish_post_to_inbox`:

```python
elif activity.has_type(ap.ActivityType.ANNOUNCE):
    back.inbox_announce(MY_PERSON, activity)
```

`inbox_announce` ([src/micronote/activitypub.py#L348](../../src/micronote/activitypub.py#L348)) called:

```python
self.DB.activities.update_one(
    {"remote_id": announce.id},
    {
        "$set": {
            "meta.object": obj.to_dict(embed=True),
            "meta.object_actor": _actor_to_meta(obj.get_actor_sync()),
        }
    },
)
```

When an `Announce` references a post on a remote server enforcing Mastodon's `AUTHORIZED_FETCH=true` (Secure Mode) or with private profile visibility, `obj.get_actor_sync()` performs an unauthenticated HTTP GET to dereference the note's author. The remote server responds with `HTTP 401 Unauthorized`, raising `active_boxes.errors.ActivityUnavailableError`:

```text
ERROR:micronote.tasks:failed to finish post to inbox for https://mas.to/users/veer66/statuses/117279205452392879/activity
Traceback (most recent call last):
  File "/app/.venv/lib64/python3.14/site-packages/micronote/worker.py", line 372, in finish_post_to_inbox
    back.inbox_announce(MY_PERSON, activity)
  File "/app/.venv/lib64/python3.14/site-packages/micronote/activitypub.py", line 85, in wrapper
    return f(*args, **kwargs)
  File "/app/.venv/lib64/python3.14/site-packages/micronote/activitypub.py", line 348, in inbox_announce
    "meta.object_actor": _actor_to_meta(obj.get_actor_sync()),
  File "/app/.venv/lib64/python3.14/site-packages/active_boxes/activitypub.py", line 740, in get_actor_sync
    return _run_sync(self.get_actor())
active_boxes.errors.ActivityUnavailableError: ActivityUnavailableError("unable to fetch https://mastodon.social/users/titipat, unknown error: 401, message='Unauthorized', url='https://mastodon.social/users/titipat'", payload=None, status_code=503)
```

Because `inbox_announce` did not catch `ActivityUnavailableError` on `obj.get_actor_sync()`, the entire activity ingestion crashed.

Furthermore:
1. `tasks.py` configured `MAX_RETRIES = 9` by default, causing failing jobs with permanent 401 Unauthorized errors to churn the backlog with exponential backoff for up to 9 retries (several days).
2. Neither `finish_post_to_inbox`, `finish_post_to_outbox`, nor `cache_attachments` caught `ActivityUnavailableError`, causing unretrievable remote activities to raise unhandled exceptions and repeatedly retry.

---

## Impact

- Ingestion of boosts (`Announce`) referencing notes from servers with Authorized Fetch failed completely, preventing legitimate posts from appearing in the user's feed.
- The worker backlog became clogged with repeating failed jobs churning over 9 retries.
- Production worker logs were flooded with unhandled error tracebacks.

---

## Root Cause Analysis

1. `inbox_announce` and `outbox_announce` unconditionally invoked `_actor_to_meta(obj.get_actor_sync())` without guarding against remote dereference failures (`Error`, `ActivityUnavailableError`).
2. Like and Announce methods (`inbox_like`, `outbox_like`, `inbox_undo_like`, `outbox_undo_like`, `inbox_undo_announce`, `outbox_undo_announce`) lacked error guards around `get_object_sync()`.
3. `MAX_RETRIES` was set to a hardcoded `9` attempts, which is excessive for transient worker operations and causes unresolvable jobs to remain in the backlog for days.
4. `finish_post_to_inbox`, `finish_post_to_outbox`, and `cache_attachments` only caught `(ActivityGoneError, ActivityNotFoundError, NotAnActivityError)`, missing `ActivityUnavailableError`.

---

## Remediation Plan

1. Implement a unified helper `_safe_object_actor_meta(obj)` in `src/micronote/activitypub.py` that safely fetches `obj.get_actor_sync()`, catches errors, and falls back to `obj.attributedTo`.
2. Guard `inbox_announce` and `outbox_announce` against `ActivityUnavailableError` on both `get_object_sync()` and `get_actor_sync()`.
3. Guard `inbox_like`, `outbox_like`, `inbox_undo_like`, `outbox_undo_like`, `inbox_undo_announce`, and `outbox_undo_announce` against `(Error, Exception)` when calling `get_object_sync()`.
4. In `src/micronote/worker.py`:
   - Reuse `activitypub._safe_object_actor_meta(obj)` in `cache_object` to eliminate duplicate logic.
   - Catch `ActivityUnavailableError` in `finish_post_to_inbox`, `finish_post_to_outbox`, and `cache_attachments` to skip unretrievable activities without retry.
   - In `run_job`, support `MICRONOTE_REMOVE_FAILED_JOBS` to delete permanently failed jobs if configured, otherwise retaining them as `status: STATUS_FAILED` (ignored by `drain_jobs` and change streams).
5. In `src/micronote/tasks.py`:
   - Reduce default `MAX_RETRIES` from 9 to 3, and support `MICRONOTE_MAX_RETRIES` environment variable configuration.
6. Guard `obj.get_actor_sync()` and `data.get_actor_sync()` in `src/micronote/admin.py` when looking up Announce activities.

---

## Resolution

- In [src/micronote/activitypub.py](../../src/micronote/activitypub.py):
  - Added `_safe_object_actor_meta(obj)` to safely dereference the actor of an object with fallback to `obj.attributedTo` or `obj.actor` metadata dict.
  - Updated `inbox_announce` and `outbox_announce` to use `_safe_object_actor_meta` and guard `get_object_sync()` against `ActivityUnavailableError` and `NotAnActivityError`.
  - Added exception handling to `inbox_like`, `outbox_like`, `inbox_undo_like`, `outbox_undo_like`, `inbox_undo_announce`, and `outbox_undo_announce`.
- In [src/micronote/worker.py](../../src/micronote/worker.py):
  - Replaced duplicate actor extraction logic in `cache_object` with `activitypub._safe_object_actor_meta(obj)`.
  - Added `ActivityUnavailableError` handlers to `finish_post_to_inbox`, `finish_post_to_outbox`, and `cache_attachments` to log a warning and skip without retrying.
  - Added `REMOVE_FAILED_JOBS` setting to allow removing permanently failed jobs upon exceeding `MAX_RETRIES`.
- In [src/micronote/tasks.py](../../src/micronote/tasks.py):
  - Changed default `MAX_RETRIES` to `3` (configurable via `MICRONOTE_MAX_RETRIES`).
- In [src/micronote/admin.py](../../src/micronote/admin.py):
  - Added safe actor dereferencing for Announce activities in the `/admin/lookup` endpoint.
- Added comprehensive unit tests in [tests/test_announce_handling.py](../../tests/test_announce_handling.py) verifying 401 handling during `inbox_announce`, `finish_post_to_inbox`, and worker retry threshold exhaustion.
