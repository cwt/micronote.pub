## Defect Description

In [app.py:384-424](../../src/micronote/app.py#L384-L424), the homepage (`/`) caches the fully-rendered HTML response in `DB.cache2` for unauthenticated visitors:

```python
cache_arg = f"{request.args.get('older_than', '')}:{request.args.get('newer_than', '')}"
cached = _get_cached("html", cache_arg)
if cached:
    return cached
...
pinned = list(DB.activities.find(q_pinned))
...
resp = render_template("index.html", outbox_data=outbox_data, pinned=pinned, ...)
_cache(resp, "html", cache_arg)
return resp
```

In [config.py:163](../../src/micronote/config.py#L163), the cache TTL is set to 12 hours:

```python
DB.cache2.create_index("date", expireAfterSeconds=3600 * 12)
```

When an administrator pins or unpins a note via `/api/note/pin` or `/api/note/unpin` in [api.py:161-184](../../src/micronote/api.py#L161-L184):

```python
@blueprint.route("/api/note/pin", methods=["POST"])
@api_required
def api_pin():
    note = _user_api_get_note(from_outbox=True)
    DB.activities.update_one(
        {"activity.object.id": note.id, "box": Box.OUTBOX.value},
        {"$set": {"meta.pinned": True}},
    )
    return _user_api_response(pinned=True)
```

`DB.cache2` is not invalidated. While normal outbox publishing (`tasks.post_to_outbox`) and worker completion (`worker.finish_post_to_outbox`) call `DB.cache2.delete_many({})`, the pin and unpin operations bypass this completely.

### Sanitization & XSS Analysis

An earlier hypothesis suggested that caching raw rendered HTML might enable stored XSS by bypassing bleach sanitization. Verification shows that note content is passed through the `clean` filter (`bleach.clean`) **during** template rendering before the output HTML is cached. Storing sanitized HTML does not bypass bleach; the defect is strictly an operational cache consistency failure.

## Impact

- Anonymous visitors receive stale homepage content for up to 12 hours after a pin or unpin action.
- Newly pinned notes fail to appear, and unpinned notes continue to display at the top of the feed until the 12-hour TTL expires or another action invalidates the cache.

## Remediation Plan

Invalidate `DB.cache2` in both `api_pin` and `api_unpin`:

```python
@blueprint.route("/api/note/pin", methods=["POST"])
@api_required
def api_pin():
    note = _user_api_get_note(from_outbox=True)
    DB.activities.update_one(
        {"activity.object.id": note.id, "box": Box.OUTBOX.value},
        {"$set": {"meta.pinned": True}},
    )
    DB.cache2.delete_many({})
    return _user_api_response(pinned=True)
```
