# Open Redirect Vulnerability via Protocol-Relative URL Bypass in safe_next_url

---

## Vulnerability & Defect Description

The redirect sanitizer `safe_next_url` ([src/micronote/utils/login.py](../../src/micronote/utils/login.py#L7-L14)) implements:

```python
def safe_next_url(value: str | None, fallback: str) -> str:
    """Returns value only when it is a relative path on this host."""
    if not value:
        return fallback
    parsed = urlparse(value)
    if parsed.scheme or parsed.netloc or not parsed.path.startswith("/"):
        return fallback
    return value
```

When evaluated against a protocol-relative URL such as `///evil.com` or `////attacker.com`:
- `parsed.scheme` is `""`
- `parsed.netloc` is `""`
- `parsed.path` is `"///evil.com"`
- `parsed.path.startswith("/")` is `True`

Consequently, the function returns `"///evil.com"`. Modern browsers parse leading triple or quadruple slashes as protocol-relative URLs (`//evil.com`), triggering an external redirect to an attacker's domain following successful login.

---

## Impact

- Allows attackers to craft convincing phishing links targeting instance administrators:
  `https://instance.tld/login?redirect=///attacker.com/fake-login`
- After valid credentials are confirmed, the user is seamlessly redirected off-site to the phishing page.

---

## Root Cause Analysis

Relying solely on `urlparse`'s `scheme` and `netloc` without validating that the raw path does not begin with multiple slashes (e.g. `//`).

---

## Remediation Plan

Ensure the path starts with exactly one forward slash and no following slash or backslash:

```python
def safe_next_url(value: str | None, fallback: str) -> str:
    """Returns value only when it is a strictly relative path on this host."""
    if not value:
        return fallback
    parsed = urlparse(value)
    if parsed.scheme or parsed.netloc:
        return fallback
    if not parsed.path.startswith("/") or parsed.path.startswith("//") or "\\" in value:
        return fallback
    return value
```
