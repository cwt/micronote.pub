## Defect Description

`outbox_delete` at [activitypub.py:526-548](../../src/micronote/activitypub.py#L526-L548) calls `delete.get_object_sync()` three separate times:

```python
def outbox_delete(self, as_actor: ap.Person, delete: ap.Delete) -> None:
    self.DB.activities.update_one(
        {"activity.object.id": delete.get_object_sync().id},   # call 1
        {"$set": {"meta.deleted": True}},
    )
    obj = delete.get_object_sync()                               # call 2
    if delete.get_object_sync().ACTIVITY_TYPE != ap.ActivityType.NOTE:  # call 3
        create_doc = self.DB.activities.find_one(
            {
                "activity.object.id": delete.get_object_sync().id,     # call 4
                ...
            }
        )
```

The same pattern appears in `inbox_delete` at [lines 502-515](../../src/micronote/activitypub.py#L502-L515) with two calls to `delete.get_object_sync()` on the condition and inside the query.

`get_object_sync()` on a `Delete` activity whose object is a bare IRI (the common case — ActivityPub Delete activities carry `object` as a URL string) resolves the IRI. When the object is not already cached in `ACTORS_CACHE` or `DB.actors`, each call triggers a synchronous HTTP fetch. The object is the same across all calls, so 3-4 identical fetches occur per delete.

## Impact

- Each delete of a remote note costs 3-4 serial HTTP requests instead of 1, increasing worker latency by ~3× for that job.
- Under heavy delete bursts (account purges, cascading deletions), the redundancy multiplies and can saturate the worker's retry budget.
- The `ACTIVITY_TYPE` check at call 3 is redundant with the type check that would have been done after call 2; the result of call 2 already gives the object.

## Remediation Plan

Hoist the object fetch to a single call and reuse it:

```python
def outbox_delete(self, as_actor: ap.Person, delete: ap.Delete) -> None:
    obj = delete.get_object_sync()
    self.DB.activities.update_one(
        {"activity.object.id": obj.id},
        {"$set": {"meta.deleted": True}},
    )
    if obj.ACTIVITY_TYPE != ap.ActivityType.NOTE:
        create_doc = self.DB.activities.find_one(
            {"activity.object.id": obj.id, "type": ap.ActivityType.CREATE.value}
        )
        ...
```

Apply the same fix to `inbox_delete`.
