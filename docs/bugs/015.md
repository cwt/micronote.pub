## Defect Description

`outbox_delete` at [activitypub.py:526-548](../../src/micronote/activitypub.py#L526-L548) calls `delete.get_object_sync()` up to four separate times:

```python
def outbox_delete(self, as_actor: ap.Person, delete: ap.Delete) -> None:
    self.DB.activities.update_one(
        {"activity.object.id": delete.get_object_sync().id},   # call 1
        {"$set": {"meta.deleted": True}},
    )
    obj = delete.get_object_sync()                               # call 2
    if delete.get_object_sync().ACTIVITY_TYPE != ap.ActivityType.NOTE:  # call 3
        create_doc = self.DB.activities.find_one(
            {
                "activity.object.id": delete.get_object_sync().id,     # call 4
                ...
            }
        )
```

The same pattern appears in `inbox_delete` at [lines 500-512](../../src/micronote/activitypub.py#L500-L512) with three separate calls to `delete.get_object_sync()`.

### Codebase Validation & Memoization Analysis

An initial hypothesis assumed that each call to `get_object_sync()` on bare IRI objects triggers a separate remote HTTP request, tripling or quadrupling network I/O. 

However, deep inspection and verification of `active_boxes.activitypub.BaseActivity.get_object()` shows internal memoization:

```python
if self.__obj:
    return self.__obj
...
self.__obj = p
return p
```

Once dereferenced on the first call, `self.__obj` is cached directly on the activity instance. Subsequent calls to `delete.get_object_sync()` on that same instance return immediately from memory without making duplicate network requests.

## Impact

- **Network I/O**: None. Duplicate HTTP requests are prevented by `active_boxes`'s internal memoization.
- **Code Maintainability**: Redundant method calls make the code harder to read, violate DRY, and create inconsistency with other handler methods that assign `obj` once at entry.
- **Error Handling**: If resolution fails, it raises on call 1; however, subsequent scattered invocations obscure where failures originate.

## Remediation Plan

Hoist the object fetch to a single call at the top of both methods and reuse `obj`:

```python
def outbox_delete(self, as_actor: ap.Person, delete: ap.Delete) -> None:
    obj = delete.get_object_sync()
    self.DB.activities.update_one(
        {"activity.object.id": obj.id},
        {"$set": {"meta.deleted": True}},
    )
    if obj.ACTIVITY_TYPE != ap.ActivityType.NOTE:
        create_doc = self.DB.activities.find_one({"activity.object.id": obj.id, "type": ap.ActivityType.CREATE.value})
        if not create_doc:
            return
        obj = ap.parse_activity(create_doc["activity"]).get_object_sync()

    self.DB.activities.update_many(
        {"meta.object.id": obj.id},
        {"$set": {"meta.undo": True, "meta.extra": "object deleted"}},
    )
    self._handle_replies_delete(as_actor, obj.inReplyTo)
```

Apply the identical consolidation to `inbox_delete`.
