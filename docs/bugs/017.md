# serve_grid_file Content-Type Fallback Allows MIME Confusion on /uploads Endpoint

## Metadata Summary

| Attribute | Value |
| --- | --- |
| **Bug ID** | BUG-017 |
| **Severity** | Medium |
| **Component** | Media Serving (`app.py`) |
| **Lifecycle Status** | Resolved |
| **Target Files** | [src/micronote/app.py](../../src/micronote/app.py#L228-L245) |

---

## Defect Description

`serve_grid_file` at [app.py:236](../../src/micronote/app.py#L236) builds the response:

```python
resp = app.response_class(data, mimetype=(grid_out.metadata or {}).get("content_type"))
```

When `metadata["content_type"]` is `None` (which happens for uploads where `mimetypes.guess_type(filename)[0]` returned `None` — e.g. files with unknown extensions), Flask falls back to `text/html` for `mimetype=None`. The raw or gzip-compressed bytes are then served with `Content-Type: text/html`.

For the `/uploads/<oid>/<fname>` endpoint the `fname` path segment is user-influenced (it comes from the original upload filename), and `save_upload` sets `mimetype` from `mimetypes.guess_type(filename)[0]`. If the guess returns `None` (e.g. a `.dat` file), the stored `content_type` is `None`, and the served response claims to be HTML. A browser that follows the link will execute any embedded script.

Additionally, `Content-Encoding: gzip` is set at [line 244](../../src/micronote/app.py#L244) when the first two bytes are `\x1f\x8b` — but this branch also fires for:
1. The gzip-compressed non-image upload path in `save_upload` ([media.py:204-206](../../src/micronote/utils/media.py#L204-L206)), which stores gzip bytes with `content_type=None` for unknown MIME types served via `/uploads/<oid>/<fname>`.
2. The remote attachment caching path in `_cache_generic_attachment` ([media.py:155-174](../../src/micronote/utils/media.py#L155-L174)), which downloads arbitrary remote attachments, gzip-compresses them, and stores `content_type=mimetypes.guess_type(url)[0]` (which is `None` for unmapped extensions), served via `/media/<media_id>`.

The combination of `text/html` fallback + gzip-compressed body + browser HTML parsing = stored XSS vector reachable both via local uploads and remote federated activities.

## Impact

- An attacker who federates a note containing an attachment with an unrecognized extension (e.g. `.bin` or `.dat` containing HTML) will have their payload fetched by the background worker, gzip-compressed, stored with `content_type=None`, and served from `/media/<media_id>` with `Content-Type: text/html` and `Content-Encoding: gzip`.
- An authenticated user uploading a file with an unrecognized extension via `/api/new_note` can store a gzip-compressed HTML payload served from `/uploads/` with `Content-Type: text/html`.
- Even without the gzip path: any upload or cached attachment with `mimetypes.guess_type` returning `None` serves as `text/html`.

## Remediation Plan

1. In `serve_grid_file`, when `mimetype` is `None`, serve with `application/octet-stream` instead of relying on Flask's default:
   ```python
   content_type = (grid_out.metadata or {}).get("content_type") or "application/octet-stream"
   resp = app.response_class(data, mimetype=content_type)
   ```
2. In `save_upload`, when `mimetypes.guess_type(filename)[0]` is `None` for a non-image file, store `content_type="application/octet-stream"` in the metadata.

## Resolution

- In [src/micronote/app.py](../../src/micronote/app.py):
  - Updated `serve_grid_file` to fall back to `application/octet-stream` whenever metadata `content_type` is None, preventing Flask from defaulting to `text/html; charset=utf-8`.
  - Added header `X-Content-Type-Options: nosniff` to protect against browser MIME-sniffing.
- In [src/micronote/utils/media.py](../../src/micronote/utils/media.py):
  - Added fallback `mtype = mtype or "application/octet-stream"` in `save_upload`.
  - Added fallback `application/octet-stream` in `_cache_generic_attachment` and `_cache_generic_emoji`.
  - Fixed context manager buffer lifecycle to ensure `buf.getvalue()` is retrieved before closing `BytesIO`.
- Added unit tests in [tests/test_media_worker.py](../../tests/test_media_worker.py) verifying `serve_grid_file` falls back to `application/octet-stream` with `X-Content-Type-Options: nosniff` and `save_upload` handles unknown extensions securely.
