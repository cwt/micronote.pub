# _PENDING_CACHE_JOBS DB Dedup Query Is Kind-Blind, Silently Drops Jobs

## Defect Description

In `_enqueue_media_cache` at [filters.py:81-110](../../src/micronote/filters.py#L81-L110):

```python
cache_key = (kind, url)
if cache_key in _PENDING_CACHE_JOBS:
    return
_PENDING_CACHE_JOBS[cache_key] = True

try:
    existing = DB.jobs.find_one(
        {
            "type": "cache_media_item",
            "iri": url,
            "status": {"$in": ["pending", "processing"]},
        }
    )
    if existing:
        return

    from micronote.tasks import enqueue_job

    enqueue_job("cache_media_item", iri=url, payload={"kind": kind.value})
```

The in-memory guard `_PENDING_CACHE_JOBS` correctly keys on `(kind, url)`. However, the database check against `DB.jobs` queries only:

```python
{"type": "cache_media_item", "iri": url, "status": {"$in": ["pending", "processing"]}}
```

This query completely ignores the `kind` field stored in `payload.kind`.

### Worker Processing

In [worker.py:541-555](../../src/micronote/worker.py#L541-L555), `cache_media_item` extracts `kind = Kind(kind_str)` from `job.payload.kind` and delegates to `MEDIA_CACHE.cache(url, kind)`. Each kind performs different caching actions:
- `Kind.ACTOR_ICON`: Caches sizes `50` and `80`.
- `Kind.ATTACHMENT`: Caches size `720` (thumbnail) and `None` (original).
- `Kind.OG_IMAGE`: Caches size `100`.
- `Kind.CUSTOM_EMOJI`: Caches size `128`.

If a `cache_media_item` job for a URL is queued as `Kind.ACTOR_ICON`, and a template concurrently triggers `_enqueue_media_cache` for the same URL as `Kind.ATTACHMENT`, the database check sees a pending job for that `iri` and returns early. The attachment job is never enqueued, leaving the attachment un-cached and un-rendered.

## Impact

- If a URL is referenced under multiple media kinds (e.g. self-hosted instances serving avatars and media from identical paths), whichever job is queued first suppresses the second kind from being enqueued.
- Discrepancy between the in-memory cache guard (`(kind, url)`) and the DB persistence guard (`iri` only).

## Remediation Plan

Add `payload.kind` to the DB deduplication query:

```python
existing = DB.jobs.find_one(
    {
        "type": "cache_media_item",
        "iri": url,
        "payload.kind": kind.value,
        "status": {"$in": ["pending", "processing"]},
    }
)
```
