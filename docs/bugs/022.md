# admin.html Receives Unused 'instances' Variable from Empty Collection Query

## Defect Description

In `admin()` at [admin.py:74-80](../../src/micronote/admin.py#L74-L80):

```python
return render_template(
    "admin.html",
    instances=list(DB.instances.find()),
    ...
)
```

However:
1. [src/micronote/templates/admin.html](../../src/micronote/templates/admin.html) contains no reference to `instances`. The template only references `inbox_size`, `outbox_size`, `col_followers`, `col_following`, and `col_liked`.
2. A codebase-wide search shows that `DB.instances` is never written to anywhere. No inserts or updates to `instances` exist.
3. The query `list(DB.instances.find())` forces a cursor iteration on every `/admin` dashboard load for an unused, perpetually empty collection.

## Impact

- Pointless database query executed on every visit to `/admin`.
- Dead code in the template context that misleadingly suggests the admin dashboard tracks external instances.

## Remediation Plan

Remove `instances=list(DB.instances.find())` from the `render_template` call in `admin.py`. If tracking federated instances is desired for future features, implement the tracking collection and UI intentionally.
