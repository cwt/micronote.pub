## Defect Description

Follow-up to BUG-025: the deterministic YouTube card only covered **video** URLs (`youtu.be/<id>`, `watch?v=`, `/shorts/`, `/embed/`, `/live/`). A note whose link is a **channel** URL (e.g. `https://youtube.com/@babylon5` in outbox note `ea3485916349a141`) still stores `meta.og_metadata = []` and renders no card.

## Root Cause

Channel metadata has no stable *deterministic* source (no oEmbed, no derivable avatar URL), and the channel link had previously ended up with an empty `og_metadata` when scraped (consent-gated shell / unavailable og data at the time):

| Source | Result |
| --- | --- |
| `GET https://www.youtube.com/oembed?url=https://www.youtube.com/@babylon5&format=json` | `404 Not Found` — oEmbed supports video URLs only (verified from `cwt-02`) |
| Channel avatar | Served from `yt3.googleusercontent.com` / `yt3.ggpht.com` under a hashed URL that is not derivable from the handle without reading the page |
| Channel page — **re-verified 2026-10-03 from `cwt-02`** | Serves **real** `og:` tags (title, description, avatar `og:image`) with or without a consent cookie and for bot-style UAs — unlike the consent-gated watch page (BUG-025) |

So the channel card can be built by scraping the channel page, with a deterministic fallback when that fails.

## Impact

- Channel links render as plain links (or, after the intermediate fix, a text-only card with no thumbnail). Low severity: the link works; only the preview quality is affected.
- A secondary latent issue: the link-card template rendered an unconditional `<img src="{{ og.image | get_og_image_url }}">`, so any card without an `og:image` (including ordinary scraped sites that omit it) would render a broken image element.

## Resolution

Added a channel branch to the YouTube short-circuit in [opengraph.py](../../src/micronote/utils/opengraph.py):

- `_youtube_channel(url)` — recognizes the `/@handle`, `/channel/<id>`, `/user/<name>`, and `/c/<name>` forms (any of the YouTube hosts; `youtu.be` is video-only).
- `_youtube_channel_card(canonical, title, user_agent)` — **scrapes the channel page** for the Open Graph tags: channel name (`og:title`), description, and the square avatar (`og:image`, not the 2560px banner). If the fetch fails or yields no `og:url`, it falls back to the deterministic **text-only** card (title = handle or name, `description` = "YouTube channel", no `image` key), so the card still renders.

Supporting changes:

- `fetch_og_metadata` now tries the video card, then the channel card, before falling through to the generic scrape — so channel URLs never hit a wasteful AP `lookup()`.
- [templates/utils.html](../../src/micronote/templates/utils.html): the `<img>` in the `og-link` card is now conditional on `og.image` being present (fixes the latent broken-image case and lets the text-only fallback render without a thumbnail).
- [handlers.py](../../src/micronote/handlers.py#L185-L191) skips image caching when `og.get("image")` is falsy, and caches the avatar URL otherwise — no handler change needed.

Tests in [tests/test_opengraph.py](../../tests/test_opengraph.py): channel URL variants (handle / channel id / user / c, plus non-channel URLs returning `None`), the successful scrape (asserting only the channel page is fetched, not oEmbed), and the text-only fallback when the page is unreachable.

## Deployment note

Requires a redeploy of `cwt-02`. After deploying, re-run the backfill (`scripts/backfill_og.py`, default scope matches any note containing a `youtu`/`youtube` substring, so channel-link notes are covered):

```sh
podman exec -i micronote-worker python - < scripts/backfill_og.py
```

Known example affected note: `outbox/ea3485916349a141` (links `youtube.com/@babylon5` → "Babylon 5" with avatar).
