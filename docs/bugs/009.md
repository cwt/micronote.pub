## Defect Description

In `admin_notifications` ([src/micronote/admin.py#L217-L234](../../src/micronote/admin.py#L217-L234)):

```python
replies_query = {
    "type": ActivityType.CREATE.value,
    "activity.object.inReplyTo": {"$regex": f"^{BASE_URL}"},
}
announced_query = {
    "type": ActivityType.ANNOUNCE.value,
    "activity.object": {"$regex": f"^{BASE_URL}"},
}
likes_query = {
    "type": ActivityType.LIKE.value,
    "activity.object": {"$regex": f"^{BASE_URL}"},
}
```

`BASE_URL` contains unescaped dots (e.g. `https://my-blog.pub` or `http://127.0.0.1:5005`). In regular expressions, an unescaped dot matches *any* character.

---

## Impact

- If `BASE_URL` is `https://my.blog`, the regex `^https://my.blog` will match domains like `https://myXblog.com`, leaking or misattributing notifications from foreign domains that match the wildcards.

---

## Root Cause Analysis

Interpolating dynamic URLs directly into database regular expression patterns without calling `re.escape()`.

---

## Remediation Plan

Escape `BASE_URL` using `re.escape`:

```python
import re

escaped_base = re.escape(BASE_URL)
replies_query = {
    "type": ActivityType.CREATE.value,
    "activity.object.inReplyTo": {"$regex": f"^{escaped_base}"},
}
announced_query = {
    "type": ActivityType.ANNOUNCE.value,
    "activity.object": {"$regex": f"^{escaped_base}"},
}
likes_query = {
    "type": ActivityType.LIKE.value,
    "activity.object": {"$regex": f"^{escaped_base}"},
}
```
