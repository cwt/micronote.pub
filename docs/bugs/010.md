## Defect Description

In `build_inbox_json_feed` ([src/micronote/activitypub.py#L628-L641](../../src/micronote/activitypub.py#L628-L641)):

```python
items = list(DB.activities.find(q, limit=50).sort("_id", -1))
data = []
for item in items:
    actor = ap.get_backend().fetch_iri_sync(item["activity"]["actor"])
    data.append(
        _feed_item(
            item,
            author={
                "name": actor.get("name", actor.get("preferredUsername")),
                "url": actor.get("url"),
                "avatar": actor.get("icon", {}).get("url"),
            },
        )
    )
```

For every request to `/api/stream`, the function executes up to **50 synchronous, serial HTTP requests over the public internet** to fetch actor profiles.

Moreover, if any of those remote Fediverse servers is offline, unreachable, or returns a 404/410 status code, `fetch_iri_sync` raises an unhandled exception (`ActivityGoneError`, `ActivityNotFoundError`, or `requests.HTTPError`) without any `try...except` protection.

---

## Impact

- Requests to `/api/stream` take 10–30+ seconds or time out entirely under normal conditions.
- If even a single remote actor among the 50 items has a deleted account or unreachable server, the entire endpoint crashes with an HTTP 500 error.
- Severely monopolizes Gunicorn threads, degrading site responsiveness for all users.

---

## Root Cause Analysis

- Neglecting to use the locally cached actor metadata already stored in `item["meta"]["actor"]` or `DB.actors`.
- Executing blocking network I/O inside a synchronous request handler loop.

---

## Remediation Plan

Read author metadata directly from the pre-cached `item["meta"]["actor"]` or query `DB.actors`, falling back to the actor IRI if not yet cached:

```python
missing_iris = {
    item.get("activity", {}).get("actor")
    for item in items
    if not item.get("meta", {}).get("actor") and item.get("activity", {}).get("actor")
}
cached_actors: dict[str, dict[str, Any]] = {}
if missing_iris:
    for actor_doc in DB.actors.find({"remote_id": {"$in": list(missing_iris)}}):
        remote_id = actor_doc.get("remote_id")
        if remote_id and actor_doc.get("data"):
            cached_actors[remote_id] = actor_doc["data"]

data = []
for item in items:
    activity = item.get("activity", {})
    actor_iri = activity.get("actor")
    meta_actor = item.get("meta", {}).get("actor")
    if not meta_actor and actor_iri:
        meta_actor = cached_actors.get(actor_iri, {})

    if not isinstance(meta_actor, dict):
        meta_actor = {}

    name = meta_actor.get("name") or meta_actor.get("preferredUsername") or actor_iri or ""
    url = meta_actor.get("url") or actor_iri or ""
    icon = meta_actor.get("icon")
    avatar = icon.get("url") if isinstance(icon, dict) else None

    author_info = {
        "name": name,
        "url": url,
        "avatar": avatar,
    }
    data.append(_feed_item(item, author=author_info))
```

---

## Resolution

- In [src/micronote/activitypub.py](../../src/micronote/activitypub.py), refactored `build_inbox_json_feed` to completely eliminate blocking synchronous network calls (`fetch_iri_sync`).
- Prioritizes pre-cached actor data in `item["meta"]["actor"]`, batch-queries any missing actors from local `DB.actors`, and provides safe fallbacks to the actor IRI if not yet cached.
- Prevents remote server timeouts, unreachable hosts, or 404/410 errors from crashing the stream feed or tying up web worker threads.
- Added comprehensive unit tests in [tests/test_stream_feed.py](../../tests/test_stream_feed.py) asserting zero network calls occur during inbox stream feed generation.
