# /drop_cache Route Has No DEBUG_MODE Guard and Can Wipe Production Caches

## Metadata Summary

| Attribute | Value |
| --- | --- |
| **Bug ID** | BUG-021 |
| **Severity** | Medium |
| **Component** | Admin / Maintenance (`app.py`) |
| **Lifecycle Status** | Resolved |
| **Target Files** | [src/micronote/app.py](../../src/micronote/app.py#L349-L354) |

---

## Defect Description

[app.py:349-354](../../src/micronote/app.py#L349-L354):

```python
@app.route("/drop_cache")
@login_required
def drop_cache():
    DB.actors.drop()
    DB.cache2.delete_many({})
    return "Done"
```

The `/api/debug` endpoint in [api.py:212-221](../../src/micronote/api.py#L212-L221) correctly guards its destructive `DELETE` branch behind `DEBUG_MODE`:

```python
if not DEBUG_MODE:
    return flask_jsonify(message="DEBUG_MODE is off")
if request.method == "DELETE":
    _drop_db()
```

`/drop_cache` has no such guard. It is only `@login_required`, so any authenticated admin in a production environment (where `DEBUG_MODE` is `false`) can wipe the entire `actors` collection and all cached pages with a single GET request. The route also accepts GET (no CSRF protection via `csrf.protect()`), making it trivially triggerable via an `<img>` tag or link click from a cross-site context (the `@login_required` check only requires the session cookie to be present, which is sent cross-site on same-origin requests).

## Impact

- Loss of all cached actor profiles: the next batch of inbox activities will trigger remote re-fetches for every follower, causing a thundering-herd effect on the federation network.
- Loss of all cached HTML pages: every page render falls back to full DB queries until the cache re-populates.
- No confirmation prompt or audit log entry.

## Remediation Plan

Add a `DEBUG_MODE` guard matching `/api/debug`:

```python
@app.route("/drop_cache")
@login_required
def drop_cache():
    if not DEBUG_MODE:
        return flask_jsonify(message="DEBUG_MODE is off"), 403
    DB.actors.drop()
    DB.cache2.delete_many({})
    return "Done"
```

Also restrict to `POST` to avoid accidental GET-triggered wipes:

```python
@app.route("/drop_cache", methods=["POST"])
```

## Resolution

- In [src/micronote/app.py](../../src/micronote/app.py):
  - Changed `/drop_cache` from `GET` to `POST` to prevent accidental or cross-site GET-triggered execution.
  - Added `if not DEBUG_MODE: return flask_jsonify(message="DEBUG_MODE is off"), 403` to prevent cache deletion on production instances.
  - Added explicit `csrf.protect()` call to prevent CSRF exploits.
- Added unit tests in [tests/test_drop_cache.py](../../tests/test_drop_cache.py) verifying that GET requests are rejected (405), requests with `DEBUG_MODE=False` return 403, and requests with `DEBUG_MODE=True` succeed.
