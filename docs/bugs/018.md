## Defect Description

[filters.py:27](../../src/micronote/filters.py#L27) declares:

```python
_GRIDFS_CACHE: dict[tuple[Kind, str, int | None], str] = {}
```

This dict is populated by `_get_file_url` at [line 124](../../src/micronote/filters.py#L124) and never evicted. Each unique `(Kind, url, size)` key maps to a short string path, so individual entries are small. However, the key itself contains the full media URL, and under high-traffic conditions with many distinct attachment/icon/emoji URLs the number of entries is unbounded.

More critically, the cache is per-process. Each Gunicorn worker maintains its own `_GRIDFS_CACHE`, so the total memory footprint scales with `num_workers × num_unique_media_urls`. The values are also `GridOut` references held indirectly — though only the path string is stored, the `GridOut` objects returned by `MEDIA_CACHE.get_file` at [line 120](../../src/micronote/filters.py#L120) are not kept, so this is not a hard leak of GridOut. The real issue is unbounded key growth.

## Impact

- Memory grows linearly with the number of distinct media URLs ever served by that process.
- After a long-running deploy (weeks/months), each worker can accumulate tens of thousands of entries.
- No TTL or size cap, so entries are never reclaimed.

## Remediation Plan

Replace the plain dict with a bounded `TTLCache`:

```python
from cachetools import TTLCache

_GRIDFS_CACHE: TTLCache = TTLCache(maxsize=4096, ttl=3600)
```

This caps memory at ~4096 entries per worker and automatically evicts entries older than 1 hour (media URLs are stable, so 1-hour TTL is safe).
