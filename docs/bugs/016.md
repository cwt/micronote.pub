## Defect Description

Two separate functions implement the same "post activity to outbox" sequence:

**`tasks.post_to_outbox`** ([tasks.py:93-105](../../src/micronote/tasks.py#L93-L105)):
```python
def post_to_outbox(activity: ap.BaseActivity) -> str:
    if activity.has_type(ap.CREATE_TYPES):
        activity = activity.build_create()
    obj_id = back.random_object_id()
    activity.set_id(back.activity_url(obj_id), obj_id)
    back.save(Box.OUTBOX, activity)  # saves to DB
    DB.cache2.delete_many({})  # invalidates cache
    enqueue_job("cache_actor", iri=activity.id)
    enqueue_job("finish_post_to_outbox", iri=activity.id)
    return activity.id
```

**`MicroblogPubBackend.post_to_outbox`** ([activitypub.py:653-671](../../src/micronote/activitypub.py#L653-L671)):
```python
def post_to_outbox(self, activity: ap.BaseActivity) -> None:
    if activity.has_type(ap.CREATE_TYPES):
        activity = activity.build_create()
    self.save(Box.OUTBOX, activity)  # saves to DB
    obj_id = self.random_object_id()
    activity.set_id(self.activity_url(obj_id), obj_id)
    recipients = activity.recipients()
    ...
    for recp in recipients:
        self.post_to_remote_inbox(self.get_actor_sync(), payload, recp)  # inline HTTP
```

Both do: build Create, generate random ID, set activity ID, save to DB. The differences:
- `tasks.post_to_outbox` enqueues async jobs and invalidates the cache (the correct production path).
- `MicroblogPubBackend.post_to_outbox` does **synchronous inline HTTP delivery** to all recipients — this blocks the calling thread on every outbox post and bypasses the retry/queue system entirely.

`MicroblogPubBackend.post_to_outbox` is **not called anywhere in the current codebase** — all outbox posts go through `tasks.post_to_outbox`. It is dead code that, if ever re-enabled, would reintroduce the blocking-delivery bug that the worker queue was designed to eliminate.

## Impact

- Dead code path that contradicts the async worker architecture.
- If `back.post_to_outbox` is accidentally called instead of `tasks.post_to_outbox`, every outbox post blocks the request thread on N serial HTTP requests (one per recipient), and delivery failures are not retried.

## Remediation Plan

Remove `MicroblogPubBackend.post_to_outbox` or reduce it to a thin delegate to `tasks.post_to_outbox` to prevent accidental use.
