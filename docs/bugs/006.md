## Defect Description

In `remove_duplicate_follows` ([src/micronote/dedup.py#L9-L16](../../src/micronote/dedup.py#L9-L16)):

```python
def remove_duplicate_follows(box: str, field: str, label: str) -> None:
    seen: set[str] = set()
    query = {"box": box, "type": ActivityType.FOLLOW.value, "meta.undo": False}
    for doc in DB.activities.find(query):
        target = doc["activity"][field]
        if target not in seen:
            seen.add(target)
```

When cleaning outbox follows (`remove_duplicate_follows(Box.OUTBOX.value, "object", "following")`), the `doc["activity"]["object"]` field in ActivityPub can be represented as an embedded dictionary (e.g. `{"id": "https://remote.server/users/bob", "type": "Person"}`) instead of a simple IRI string.

Attempting to execute `seen.add(target)` with a `dict` raises:

```
TypeError: unhashable type: 'dict'
```

---

## Impact

- The operator maintenance utility `python -m micronote.dedup` crashes mid-execution whenever an embedded actor dictionary exists in outbox records, leaving duplicate records uncleared.

---

## Root Cause Analysis

Failure to extract the target string identifier (`id`) when the ActivityPub property is an embedded dictionary.

---

## Remediation Plan

Extract the string IRI from dictionary targets before adding to `seen`:

```python
target = doc["activity"].get(field)
if isinstance(target, dict):
    target = target.get("id")
if not target:
    continue
if target not in seen:
    seen.add(target)
    ...
```
